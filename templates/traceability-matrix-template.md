## Guidance

- Every important use case should link back to one or more requirements.
- Add ADR links when a use case depends on a specific design choice.
- Add test IDs once implementation starts to close the loop between docs and delivery.
- Use the matrix as a tester-facing coverage map, not only as project bookkeeping.
- Leave missing test coverage visible instead of filling gaps with vague placeholders.
