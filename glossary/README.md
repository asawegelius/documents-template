# Glossary

Keep shared domain terminology in [glossary.md](glossary.md). People and agents should use the same term for the same concept.

## Add or change a term

Add a term, its precise meaning and useful synonyms or excluded meanings. Prefer the project's language over a generic dictionary definition. Link to a requirement or decision when the definition affects behavior.

## Review checklist

- Does the term have one clear meaning in this project?
- Are acronyms expanded?
- Are confusing synonyms or homonyms explained?
- When a meaning changes, have affected requirements, use cases and tests been reviewed?

Follow [CONVENTIONS.md](../CONVENTIONS.md). Avoid duplicating long definitions in multiple documents.
